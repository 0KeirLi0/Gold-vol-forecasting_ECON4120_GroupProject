Gold Volatility Forecasting

An Applied Forecasting Methods group project exploring forecasting approaches for gold-market volatility. The project will develop iteratively, starting with methods from the course and extending the methodology as model comparisons and analysis motivate further work.

Project workflow

Each iteration follows a shared loop:

  1. Infrastructure — prepare data and repository artifacts, and support presentations.
  2. Model development — identify relevant variables and develop a forecasting model.
  3. Model analysis — compare candidate models, explain results and limitations, and recommend the next step.
  4. Next iteration — use that recommendation to guide the next round.

The analysis decision closes one round and sets the question for the next. If the next step needs new or changed data, first clarify the model-development requirements, then update the pipeline with Keir. Keep handoffs explicit: model development should share the model specification and inputs with analysis; analysis should share its evidence, limitations, and recommended next step with the team.

Early iterations may explore course methods such as AR, MA, ARMA, ARCH, GARCH, or EGARCH. As the project develops, later iterations may investigate extensions such as quantile regression or shock analysis. These are examples, not a prescribed or exhaustive method list; the team will choose methods based on project questions and findings.

Data and reproducibility

Keir selected gold futures as the Stage 2 working instrument; the current downloadable series is Yahoo Finance GC=F, a COMEX gold futures continuous series. It is not spot gold or a single fixed-expiry contract, and its history may reflect contract rolls. The CLI and notebook download daily data from Yahoo Finance by default; local CSV input is also supported. Revisit the series or instrument only by an explicit team choice, and never mix spot and futures. Yahoo’s XAUUSD=X spot ticker returned “No data found” when checked on 2026-11-06.

The pipeline computes close-to-close log returns and a forward target over the next five observed price sessions by default. The default target is realized variance, calculated as the sum of squared daily log returns; realized_volatility is also available as the square root of that sum. Horizon and target are configurable. The target uses future observations only as the label for each forecast origin; predictors in this baseline contain only information available through that origin.

Raw and prepared downloads are written under data/ and excluded from Git. Preserve them for each analysis run and record their provenance, observation date range, and pipeline options. The prepared CSV includes the forecast-origin date, close, log return, target-window dates, target value, and provider/instrument metadata. Do not mix futures and spot observations. Do not share Bloomberg or other restricted exports unless the applicable license permits it.

The pipeline preserves raw closes, rates, and volume; Enoch can choose and document further transformations for modeling. The S&P 500 input is a price index, not a total-return index. Breakeven inflation is market-implied inflation compensation, not a survey measure. Futures volume is an optional continuous-series measure, not a fixed-contract or exchange-wide volume series. Central-bank gold demand is deferred until a specific source and publication schedule support point-in-time alignment.

Run the daily predictor panel; FRED observations are downloaded as CSV directly from the public FRED website and do not require an API key:

python -m gold_vol_pipeline.predictors --start 2016-01-01 --end 2026-11-01

notebooks/04_predictors.ipynb provides a notebook interface for this CLI and previews the saved panel and manifest.

Yahoo daily closes are treated as available on their observation date because the forecast origin is after that date’s market data have been published. FRED series are conservatively treated as available on the next weekday; the prepared dataset uses the latest value available on or before each gold forecast origin and retains each source observation date. Missing predictor values remain missing; Enoch should inspect predictor freshness and choose a missing-data policy before fitting models. The one-business-day FRED lag is an availability-date proxy, not a series-specific release timestamp, and the website download returns current observations rather than historical real-time vintages. Verify release schedules and revisions before using this panel for a strict real-time backtest.

The raw downloads, prepared dataset, and run manifest are written beneath the Git-ignored data/ directory. A local normalized CSV can be used instead with --predictor-input; its date column must be the value’s availability date, with optional {predictor}_observation_date columns to retain source dates. For example:

python -m gold_vol_pipeline.predictors \
  --gold-input data/raw/gold_futures.csv \
  --gold-source "Yahoo Finance" \
  --gold-instrument "COMEX Gold Futures continuous series (GC=F)" \
  --predictor-input data/raw/stage2_predictors.csv

The selected predictor columns are dxy_close, sp500_close, sp500_log_return (close-to-close log difference), vix_close, treasury_10y_yield, breakeven_inflation_10y, and wti_spot. A gold CSV passed with --gold-input may also contain volume.

Each successful RIC request produces one CSV. The filename is the RIC with characters other than letters, digits, ., _, and - replaced by _, then leading/trailing dots and underscores removed. A RIC with no data or an error has no CSV; check download_manifest.json for its status and error message.

Field-code meanings: TRDPRC_1 is the vendor’s last-traded price field; OPEN_PRC, HIGH_1, and LOW_1 are the session open, high, and low; ACVOL_1 is accumulated trading volume; OPINT_1 is open interest; MID_PRICE is a midpoint quote; BID and ASK are bid and ask quotes. Confirm the instrument-specific field description, units, quote convention, and availability in Workspace. In particular, MID_PRICE for volatility instruments may be quoted in volatility points, while risk-reversal and butterfly signs/conventions are instrument-specific.

ALL_LSEG_DATA.xlsx has one worksheet per successful RIC, with the same Date and field columns as that RIC’s CSV. download_manifest.json records the provider, requested date range, availability caveat, and for each RIC its category, requested fields, status, returned columns, row count, and CSV name (or an error/no-data message). This export does not calculate S&P 500 returns, Treasury bid/ask midpoints, or predictor availability dates; those are later transformations and must be documented before modeling. For exact returned headers, consult the manifest because Workspace entitlements and instrument definitions can differ.

Import LSEG exports into the forecasting pipeline

The pipeline can normalize the local exports and prepare a separate LSEG dataset without overwriting the existing Yahoo/FRED Stage 2 output:

python -m gold_vol_pipeline.predictors --lseg-input-dir data/refinitiv

By default this writes normalized gold and predictor CSVs under data/raw/, plus data/processed/stage2_lseg_multivariate.csv and its manifest. The importer uses only GCc1.csv as the gold target; it never substitutes spot, fixing, GCc2, or GCc3. It drops GCc1 rows whose TRDPRC_1 close is missing, uses ACVOL_1 as volume only when that field is actually present, derives sp500_log_return from the S&P 500 closes, and derives the 10-year yield as the midpoint of BID and ASK when the Treasury file is present. Available gold implied-volatility, risk-reversal, and butterfly quotes are preserved as additional columns (gold_iv_1m, gold_iv_2m, gold_iv_3m, gold_iv_6m, gold_iv_1y, gold_1m_risk_reversal, and gold_1m_butterfly). These additional option features are not part of the existing seven-variable model specification.

All imported predictors are assigned an availability date one weekday after their observation date as a conservative proxy; both dates are retained. This does not reconstruct exact publication times or historical vintages. Files absent from the export are skipped and listed in the generated manifest. In the current local export, GCc1.csv has no ACVOL_1; breakeven-inflation and WTI files are absent, and LSEG spot/fixing requests failed. Consequently the prepared LSEG dataset is a partial predictor panel, not a replacement for the seven-variable Yahoo/FRED dataset or a drop-in input for the existing seven-variable Stage 2 model notebook. Review data/refinitiv/download_manifest.json and coordinate feature changes with model development before estimating models.

Exploratory LSEG predictor significance

The LSEG predictor screen is in notebooks/05_advanced_models.ipynb. It uses the current prepared GCc1 panel, an 80/20 chronological split, and purges training rows whose five-session target overlaps the first holdout origin. The 4,057 complete observations span 2010-01-06 through 2026-11-03; 3,241 training rows remain after purging four rows. The model regresses log1p five-session forward realized variance on standardized predictors, uses HAC standard errors with four lags, and applies Holm correction across the 11 individual predictor tests.

The five implied-volatility tenors are significant as a joint block (HAC F=17.42; Holm-adjusted p=9.26e-17 across three group tests), while the 1M risk reversal and butterfly are not jointly significant (adjusted p=0.386). Individual IV-tenor coefficients do not identify a preferred tenor: their maximum absolute pairwise training correlation is 0.991. These are exploratory conditional associations, not proof of out-of-sample predictive value or a final feature-selection decision. The dataset uses a one-weekday availability proxy, not verified historical publication times; confirm LSEG field units and quote conventions before interpreting the option results. Available results cover only the successful exports listed in the manifest.

API access and small file size do not grant redistribution rights. FRED’s series notes identify third-party copyright restrictions for some series (including S&P 500, VIX, and WTI); check each series’ terms before sharing or committing data. Keep downloaded market data local unless redistribution is explicitly permitted, and cite the source in any analysis.

Download and prepare Yahoo futures data directly (the end date is exclusive; by default it is today, avoiding a partial current-day bar):

Return-only baseline forecasts

The gold_vol_pipeline package also provides return-only variance forecasts: expanding historical variance, rolling historical variance, EWMA, AR(1) and MA(1) models of squared returns, ARCH(1), and GARCH(1,1). Each forecast function accepts returns available through a forecast origin and a configurable horizon; it returns the expected variance summed over the next horizon observations, matching the pipeline’s realized-variance target definition. GARCH(1,1) scales the returns by their root mean square during fitting and converts the forecast variance back to the original units. For example:

from gold_vol_pipeline import baseline_forecasts, prepare_dataset

dataset = prepare_dataset(prices, horizon=5)
origin_returns = dataset["log_return"].dropna()
forecasts = baseline_forecasts(origin_returns, horizon=5)

Only pass returns known at the forecast origin. These are candidate baseline forecasts, not a backtest by themselves. notebooks/02_models.ipynb performs rolling-origin comparisons against prepared targets over the latest 20 common origins and reports MAE/RMSE. The Hyndman-Khandakar order is reselected using only returns available at each origin. The current comparison uses the working GC=F series; target windows overlap and the evaluation window is small, so the results are exploratory and do not constitute a final model-selection decision.

Run exploratory diagnostics on the prepared return series with:

python -m gold_vol_pipeline.diagnostics --input data/processed/gold_futures.csv

The report includes tests for zero mean, stationarity, serial dependence, ARCH effects, and return normality. These are diagnostic checks, not proof that a model’s assumptions hold or a substitute for out-of-sample evaluation.

Model-evaluation workbench

Open notebooks/03_model_evaluation.ipynb to inspect price levels and transformations, ADF unit-root tests, ACF/PACF plots, and return diagnostics. It fits configurable AR, MA, ARMA, ARCH, GARCH, and EGARCH candidate orders and displays their model names, AIC, BIC, and convergence status in a readable table. These are in-sample criteria for the same input series; they do not choose a final project model.

The notebook also saves raw and standardized residual series under the git-ignored data/processed/ directory, plots residual panels, and applies Ljung-Box tests to residuals and squared standardized residuals. The evaluation helpers are in src/gold_vol_pipeline/model_evaluation.py.

Select a nonseasonal ARIMA model for squared returns (the volatility proxy) with the Hyndman-Khandakar stepwise procedure:

python -m gold_vol_pipeline.auto_arima --input data/processed/gold_futures.csv

The implementation uses KPSS tests to choose the differencing order and stepwise AICc search for AR/MA orders. It prints the selected order, fitted coefficients, candidate rankings, and a five-session variance-proxy forecast. Selection on the full sample is exploratory; use training-only selection inside a chronological backtest before comparing forecast performance.

Repository status

The first modeling stage uses traditional univariate time-series methods on one gold-derived series: return-only candidate forecasts, sequential rolling-origin comparisons with MAE/RMSE, exploratory diagnostics, configurable in-sample candidate comparisons, and a nonseasonal Hyndman-Khandakar ARIMA selector. The current user-directed working model is GARCH-X with lagged VIX. It has the lowest MSE in the integrated 25-model comparison, but does not significantly beat expanding historical variance after Holm correction; this is not a confirmed team-wide model decision. The concise Group 2 report focuses on this model and seven basic benchmarks. The prior broad report and presentation are preserved in archive/model_exploration_2026-11-15/. The automatic ARIMA selector remains available for exploratory comparisons. For Stage 2, Keir selected daily DXY, nominal 10-year Treasury yield, S&P 500 returns, VIX, 10-year breakeven inflation, WTI spot, and optional gold-futures volume. The pipeline is implemented in gold_vol_pipeline.predictors; it derives close-to-close log-returns for the S&P 500. An optional LSEG importer can prepare a separate dataset from data/refinitiv/; the available export includes a partial predictor panel plus gold-option quotes, while breakeven inflation, WTI, spot, and gold volume are unavailable in that snapshot. It does not replace the Yahoo/FRED panel or the current seven-feature model input. notebooks/05_advanced_models.ipynb provides an exploratory all-predictor gradient-boosting forecast with a training-only HAC-robust coefficient significance screen. In the current snapshot, only VIX remains significant after Holm correction, and the gradient-boosting model underperforms the expanding-variance benchmark on the holdout; no final multivariate model or variable-selection decision is recorded. On the separate LSEG GCc1 panel, the training-only HAC screen found DXY and VIX individually significant after Holm correction; the gold implied-volatility tenors were significant jointly but highly collinear (maximum pairwise correlation 0.991), so their individual importance is unresolved. The LSEG panel is partial, and its quote units and one-weekday availability proxy require verification. These association results do not establish out-of-sample predictive value or a final variable-selection decision. Central-bank demand remains deferred.

The integrated Stage 3 evaluation in notebooks/06_final_evaluation.ipynb refits auto-ARIMA, VAR, GJR-GARCH, asymmetric EGARCH, Student-t GARCH, VIX-GARCH-X, and quantile GARCH on the 445 weekly origins, alongside 18 cached baseline and predictor-model forecasts. Two quantile-GARCH fits failed; the 25-model common-origin comparison uses 443 observations per model. The provisional recommendation is GARCH-X with lagged VIX, using MSE as the primary criterion: MSE is 9.492e-7 (RMSE 0.000974), lowest in that sample. Asymmetric EGARCH has the lowest MAE and QLIKE; no candidate significantly beats historical variance after Holm adjustment. GARCH-X holds VIX fixed at its origin value during the forecast horizon. This is an exploratory working choice, not a confirmed team-wide decision; optimizer warnings, failed fits, source timing and overlapping targets limit the evidence.
